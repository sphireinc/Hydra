3. Fix correctness and API behavior in hydration

The current hydrator has several behavior traps.
	7.	Handle empty whereClauses explicitly
	•	current code can produce SELECT * FROM table WHERE  which is invalid SQL.
	•	I want a clear error like “at least one where clause is required”.
	8.	Return a not-found error when no row matches
	•	today fetch returns an empty map with no error if there are no rows.
	•	Hydrate() then silently leaves zero values in the struct.
	•	that is dangerous and hard to debug.
	•	I want a defined sentinel-style error or at least a clear error message.
	9.	Make type conversion safer
	•	current Hydrate() uses reflection in ways that can panic or mis-hydrate:
	•	strings only handle []byte, not plain string
	•	ints/floats assume exact runtime kinds
	•	NULL values are not handled
	•	pointer assignment is too optimistic
	•	struct/slice direct assignment is unsafe unless exactly assignable
	•	I want a dedicated conversion helper with:
	•	assignable/convertible checks
	•	nil handling
	•	sane string/int/float/bool conversions
	•	better errors when a field cannot be populated
	10.	Avoid silent partial hydration

	•	today unsupported field types can silently do the wrong thing.
	•	I want failures to be surfaced rather than masked.

	11.	Improve table-name handling

	•	current table name is just strings.ToLower(structName).
	•	that is too naive for real schemas.
	•	I want at least one override mechanism, likely via:
	•	explicit table name on Hydratable, or
	•	struct-level tag / method
	•	This will make the library usable beyond toy cases.

4. Tighten SQL safety

Values are parameterized, but identifiers are not.
	12.	Validate table and column identifiers

	•	table names and where-clause column names are concatenated directly into SQL.
	•	parameterization does not protect identifiers.
	•	I want to restrict identifiers to a safe pattern or require them from trusted metadata only.

	13.	Build column list from hydra tags instead of SELECT *

	•	SELECT * is fragile and pulls unnecessary data.
	•	long term I want to select only the tagged columns needed for hydration.
	•	This also reduces ambiguity and improves compatibility across schemas.
